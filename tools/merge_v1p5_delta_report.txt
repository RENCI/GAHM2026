Scope of this measurement
-------------------------
The environmental .mat consumed by tests 3 and 4 (tools/FLORENCE_AL06_2018.mat)
was HELD CONSTANT for this comparison. It was produced by the pre-merge
SeparateEnvHur. This isolates the GAHM solver-chain and output-path changes
from the SeparateEnvHur changes.

The SeparateEnvHur rewrite (physical-units configuration, track-eye centering,
separate filter isotach) also changes the environmental fields. Those effects
are NOT quantified here; the regenerated baselines that follow this report do
include them.

Summary of result
-----------------
  PASS: 40
  FAIL: 11
  All 11 failures are NaN-pattern changes in TC and Env velocity/pressure.
  Every GAHM parameter (B, Bg, phi, Rmax, RmaxQ, Rmax_tot, SVorMax, flag),
  every track coordinate, and all Env pressure values are BIT-IDENTICAL.

Root cause of the 11 failures
-----------------------------
Isolated by reverting each merged change individually and re-running.
Sole cause: util/gahm2026Prep.m now normalizes zero quadrant radii to NaN

    RQuad(RQuad(1:4,:) == 0) = NaN;

Effect, verified directly at the affected timesteps:

    baseline TC_VelU NaN count at t=30 : 494 of 2601 cells
    merged   TC_VelU NaN count at t=30 :   0 of 2601 cells

The merge REMOVES NaN holes; it does not introduce any. Late in the Florence
track, Vmax falls below 64 kt so the R64 isotach radii are reported as 0.
Previously those zeros propagated into the radial profile machinery and left
an undefined annulus in the output field. Treating them as missing data takes
the existing "absent isotach" path and produces defined values throughout.

Affected output times: t=30..35 in test 1 (env_type=1), t=29.. in tests 3 and 4.
These correspond to track times 2018-09-14 21:00 and 2018-09-15 00:00, where
Vmax = 63 and 60 kt respectively.

Changes verified to have NO effect on this configuration
--------------------------------------------------------
  - util/gahm2026Consistency.m check-4 loop restructure. The completion test
    moved out of the isotach loop into its own quadrant loop and now sums
    flag(q,1:3) rather than flag(q,:). GAHM.flag compares bit-identical for
    Florence, so the previous behavior happened to be harmless here. It was
    still wrong: q leaked from the closed quadrant loop and was always 4.
  - util/gahm2026Solve.m Rmax_in = NaN fallback (Rmax = 40000 m). Not reached
    for Florence, whose RMW is present at every track time.
